# F3: Does PyTorch SDPA with is_causal=True deliver O(N) memory/compute for seq-len 256–512 on consumer GPUs, and what edge cases cause silent fallback to slower kernels or degraded performance?

## Findings

### [1] Flash Attention backends achieve O(N) memory but NOT O(N) compute; compute remains O(N²) FLOPs
- quote: "The naive implementation requires O(n^2) memory for the attention matrix. Fused backends (FlashAttention, memory-efficient attention) compute this in O(n) memory by tiling the computation and never materializing the full attention matrix."
- url: https://gist.github.com/rkayaith/9eb401fddaad27d6b2edc1a496bea7fc
- source_type: primary (source-code analysis of PyTorch nightly 08b6f48d)
- published: 2026-03-11
- confidence: high

### [2] Flash Attention paper establishes O(N) HBM memory complexity with same FLOPs as standard attention
- quote: "We analyze the IO complexity of FlashAttention, showing that it requires fewer HBM accesses than standard attention, and is optimal for a range of SRAM sizes."
- url: https://arxiv.org/abs/2205.14135
- source_type: primary (peer-reviewed paper, Tri Dao et al., NeurIPS 2022)
- published: 2022-05-27
- confidence: high

### [3] SDPA auto-dispatches to FlashAttention-2, Memory-Efficient, or Math backend on CUDA based on input constraints
- quote: "All implementations are enabled by default. Scaled dot product attention attempts to automatically select the most optimal implementation based on the inputs."
- url: https://docs.pytorch.org/docs/2.13/generated/torch.nn.functional.scaled_dot_product_attention.html
- source_type: primary (official PyTorch docs v2.13)
- published: 2025 (continuously updated)
- confidence: high

### [4] FP32 inputs silently force fallback to Math backend (O(N²) memory), the most common pitfall
- quote: "UserWarning: Expected query, key and value to all be of dtype: {Half, BFloat16}. Got Query dtype: float, Key dtype: float, and Value dtype: float instead."
- url: https://github.com/pytorch/pytorch/issues/167754
- source_type: community (GitHub issue with reproduction)
- published: 2025-11-13
- confidence: high

### [5] Flash Attention requires head_dim ≤ 512; cuDNN backend further restricts to head_dim ≤ 128 on consumer GPUs (≤ 256 on Hopper)
- quote: "Head dim ≤ 512 (AOTriton 0.9+), ≤ 256 (gfx11xx on AOTriton 0.11)" and "head_dim <= 128 (256 on Hopper...)"
- url: https://gist.github.com/rkayaith/9eb401fddaad27d6b2edc1a496bea7fc
- source_type: primary (source-code analysis of cuda/sdp_utils.cpp constraint checks)
- published: 2026-03-11
- confidence: high

### [6] is_causal=True is equivalent to causal_upper_left bias and is mutually exclusive with attn_mask
- quote: "For standard autoregressive training, setting is_causal=True is highly optimized and automatically generates a lower-triangular mask."
- url: https://articles.terabox.com/hub/how-to-correctly-use-masks-in-pytorch-scaleddotproductattention
- source_type: secondary (technical article referencing PyTorch source)
- published: 2026-06-15
- confidence: medium

### [7] At seq-len 1024 with flash backend SDPA runs ~38× faster than math backend (2272 μs vs 87472 μs) on A100
- quote: "The flash attention implementation runs in 2276.705 microseconds ... The math implementation runs in 87472.361 microseconds"
- url: https://docs.pytorch.org/tutorials/intermediate/scaled_dot_product_attention_tutorial.html
- source_type: primary (official PyTorch tutorial, benchmarked on A100)
- published: 2023-03-15 (last verified 2024-11-05)
- confidence: high

### [8] PyTorch 2.5.0 on ROCm silently upcasted all SDPA to fp32, causing 2× slowdown and 26% memory increase
- quote: "The memory usage reflects this, up to 12.0GiB from 9.5GiB on 2.4.1 for a 4x128x128 latent shape."
- url: https://github.com/pytorch/pytorch/issues/135778
- source_type: community (GitHub issue, confirmed regression, milestone 2.5.0)
- published: 2024-09-12
- confidence: high

### [9] Flash Attention kernel requires fp16/bf16 dtype; SM50+ for memory-efficient; non-NVIDIA GPUs may lack fused kernels entirely
- quote: "Supported dtypes: fp16, bf16" ... "SM50+ equivalent (HIP)" ... "The impact may be as wide as all other platforms that have fp16 intrinsics but no FLASH_ATTENTION or EFFICIENT_ATTENTION sdpa kernels which is effectively every non-NVIDIA gpu from the last few years."
- url: https://gist.github.com/rkayaith/9eb401fddaad27d6b2edc1a496bea7fc and https://github.com/pytorch/pytorch/issues/135778
- source_type: primary (source code) + community
- published: 2024-09-12 / 2026-03-11
- confidence: high

### [10] cuDNN attention backend (preferred on Hopper/Blackwell) requires dropout_p to be a multiple of 1/16
- quote: "check_cudnn_dropout: Dropout probability is a multiple of 1/16"
- url: https://gist.github.com/rkayaith/9eb401fddaad27d6b2edc1a496bea7fc
- source_type: primary (source-code analysis of cuda/sdp_utils.cpp)
- published: 2026-03-11
- confidence: high

## Dead ends
- NVIDIA cuDNN docs page (docs.nvidia.com) described FlashAttention-2 algorithm but did not provide memory complexity formulas or consumer GPU constraint tables.
- DuckDuckGo query for "pytorch SDPA is_causal True memory usage 256 512 consumer GPU" returned mostly generic SDPA tutorials without specific seq-len memory measurements for 256–512 range.

## Suggested follow-ups
- Benchmark SDPA memory usage at seq-len 256 and 512 specifically on an RTX 3060/4060 (4 GB VRAM) to confirm O(N) memory savings are meaningful at these short lengths vs. O(N²) math fallback.
- Investigate whether PyTorch ≥ 2.6 fixed the ROCm fp32 upcast regression (issue #135778 was milestone 2.5.0).
- Test whether NestedTensor with is_causal=True triggers fallback in PyTorch ≥ 2.4 for training workloads.
