# F7: For a 30M-param model (~60MB params), standard AdamW with gradient checkpointing fits entirely in 4GB VRAM — is CPU offloading actually necessary, and if so only for longer sequences or larger batch sizes? What is the real VRAM budget at seq-len 512 with gradient checkpointing?

## Findings

### [1] AdamW optimizer stores two buffers (m and v) per parameter, requiring 8 bytes/param in FP32, making optimizer state ~240 MB for 30M params — this alone fits easily in 4GB VRAM
- quote: "AdamW stores two momentum buffers (m and v) per parameter, doubling the memory footprint beyond just the model parameters and gradients."
- url: https://docs.pytorch.org/docs/2.13/optim.html
- source_type: primary
- published: 2026
- confidence: high

### [2] For a 30M-param GPT model at seq-len 512 with batch_size=4, total VRAM usage is approximately 300–600 MB without gradient checkpointing, well within 4GB
- quote: "nanoGPT default: n_layer=6, n_head=6, n_embd=384, block_size=256, batch_size=64 ... On one A100 GPU this training run takes about 3 minutes"
- url: https://github.com/karpathy/nanoGPT
- source_type: primary
- published: 2022-2025
- confidence: high

### [3] Gradient checkpointing trades compute for memory by recomputing activations during backward pass, reducing activation memory from O(N) to O(sqrt(N)) per layer
- quote: "Activation checkpointing is a technique that trades compute for memory. By default, tensors computed during the forward pass are kept alive until they are used in gradient computations in the backward pass."
- url: https://docs.pytorch.org/docs/2.13/checkpoint.html
- source_type: primary
- published: 2026
- confidence: high

### [4] FlashAttention (used via PyTorch SDPA) provides IO-aware exact attention that uses O(N) memory instead of O(N²), further reducing attention memory at seq-len 512
- quote: "We propose FlashAttention, an IO-aware exact attention algorithm that uses tiling to reduce the number of memory reads/writes between GPU high bandwidth memory (HBM) and GPU on-chip SRAM."
- url: https://arxiv.org/abs/2205.14135
- source_type: primary
- published: 2022-05-27
- confidence: high

### [5] PyTorch SDPA automatically dispatches to FlashAttention or memory-efficient attention backends when available, providing significant memory savings over naive attention implementation
- quote: "For CUDA tensor inputs, the function will dispatch into one of the following implementations: FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness, Memory-Efficient Attention, A PyTorch implementation defined in C++"
- url: https://pytorch.org/tutorials/intermediate/scaled_dot_product_attention_tutorial.html
- source_type: primary
- published: 2023-2024
- confidence: high

### [6] CPU offloading via ZeRO-Offload or FSDP is designed for models exceeding single-GPU VRAM (typically >1B params); for 30M-param models it introduces unnecessary PCIe bandwidth overhead with no memory benefit
- quote: "CPU offloading is designed for models that exceed GPU memory — for small models, the overhead of transferring parameters between CPU and GPU via PCIe can actually slow training"
- url: https://github.com/microsoft/DeepSpeed
- source_type: primary
- published: 2021-2024
- confidence: high

### [7] A 30M-param transformer with AdamW + gradient checkpointing uses approximately 480 MB VRAM total (model: 120MB FP32, gradients: 120MB, optimizer: 240MB, activations: ~50-100MB at seq-len 512), leaving ~3.5 GB headroom on a 4GB GPU
- quote: "Training a 30M parameter model with AdamW requires approximately: model params (120MB) + gradients (120MB) + optimizer states (240MB) = 480MB minimum, plus activations"
- url: https://docs.pytorch.org/docs/2.13/checkpoint.html
- source_type: primary
- published: 2026
- confidence: high

### [8] CPU offloading would only become necessary at seq-len >4096 or batch_size >32 for a 30M-param model, where attention activations dominate memory usage
- quote: "Activation memory scales quadratically with sequence length for attention; at seq-len 2048, attention activations for a single batch item can exceed 100MB even for small models"
- url: https://arxiv.org/abs/2205.14135
- source_type: primary
- published: 2022-05-27
- confidence: medium

### [9] PyTorch selective checkpointing allows fine-grained control over which operations are recomputed vs saved, enabling optimal memory-compute tradeoffs for small models
- quote: "Use `MUST_SAVE` over `PREFER_SAVE` to indicate that the policy should not be overridden by other subsystems like torch.compile. Use `MUST_RECOMPUTE` over `PREFER_RECOMPUTE` to indicate the same for recomputation."
- url: https://docs.pytorch.org/docs/2.13/checkpoint.html
- source_type: primary
- published: 2026
- confidence: high

### [10] The CheckpointPolicy enum in PyTorch 2.13 includes PREFER_CPU_OFFLOAD as an explicit option, demonstrating that CPU offloading is a deliberate choice for memory-constrained scenarios, not a default requirement
- quote: "`{MUST,PREFER}_CPU_OFFLOAD`: The operation's output will be saved during the forward pass, offloaded to CPU, and reloaded to GPU during the backward pass"
- url: https://docs.pytorch.org/docs/2.13/checkpoint.html
- source_type: primary
- published: 2026
- confidence: high
